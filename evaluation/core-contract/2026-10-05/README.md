# Run 3 temporal and extension contract

All values and assignments are synthetic. The temporal companion and pharmaceutical test extension are separate, unpromoted profiles; they are not production imports or empirical case data. Protocol and expected outcomes are written before execution. Run `python tools/check_run3_core_contract.py` from the repository root.

## Temporal decisions
Assessment time is when an estimate is made; reference time identifies the time described. Neither equals database insertion time. Dimension (likelihood/impact/overall), control baseline (before/after), evaluation basis (observed/projected), scale and versioned method are separate axes. A projected residual estimate is not a measured after-treatment result. Lower numeric values do not establish treatment effectiveness. Coexistent results retain separate identities; supersession must concern the same risk and must preserve predecessors.

Qualified responsibility validity is a half-open interval [validFrom, validTo); co-owners are allowed. A future start or an end exactly equal to the query time is inactive. Missing start is unknown and excluded from this qualified rule; it is not universally ownerless. The legacy rule remains an explicitly different, uninvalidated-record shortcut until P07/P10 promotion/migration. This prototype does not make OWL infer current ownership from missing facts.

## Extension decision
The positive extension specializes an existing assessment-result class in a fresh pharmaceutical test namespace and classifies an existing constructed result. It adds a usable profile query while preserving four baseline task answers. Core source hashes must remain unchanged. Direct redefinition of core terms and equality/equivalence shortcuts are rejected by the selected extension policy. This bounded syntactic/dependency and query regression is **not** a proof of logical conservative extension for arbitrary axioms or all queries.

P07 must assign governed helper IDs/vocabulary and synchronize OWL/SHACL, definition text and migration notes; P10 must add native orthogonal context/scale/time fields and prove actual SQL/SPARQL parity; P08 must reflect these decisions in the complete editable OntoUML representation. Keep current original CQ counts unchanged: R1–R5 and the temporal/extension checks supplement them. P06 remains partial until the canonical promotion decisions are accepted.
