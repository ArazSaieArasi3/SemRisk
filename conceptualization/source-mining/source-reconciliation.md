# SemRisk Cross-Source Reconciliation

**Status:** template — populated at Gate G1 / Issue #18 after material W1 source mining.

## Required reconciliation views

1. synonym clusters;
2. homonym/polysemy conflicts;
3. competing definitions;
4. Core vs profile-specific candidates;
5. ontology vs data/product/method constructs;
6. concept-category conflicts;
7. relation/event/state conflicts;
8. source-family unique deltas;
9. reuse/align/create/defer decisions;
10. unresolved blockers tied to affected claims.

## Candidate disposition record

For each cluster record:

- reconciliation ID;
- raw source-concept IDs;
- candidate canonical label;
- source definitions/locators;
- conflict summary;
- ontology category analysis;
- scope/module/profile candidate;
- reuse/reference ontology mapping;
- decision;
- confidence;
- unresolved questions;
- CQ/evaluation relevance;
- Paper 1 relevance.

No canonical SemRisk entity is considered frozen merely because it appears in this document. Canonical registries are created only after the Source Completeness gate is explicitly passed for the relevant claim boundary.
